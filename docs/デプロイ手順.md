# デプロイ手順（Vercel + Convex）

## 本番URL

https://paint-rush-eight.vercel.app/

## 日常のデプロイ方法

初回セットアップ（下記）が完了していれば、**`main` ブランチに push / マージするだけ**で自動デプロイされる。

Vercel の GitHub 連携により `main` への push をトリガーに Build Command（`npx convex deploy --cmd 'npm run build'`）が自動実行され、

1. Convex の本番デプロイ（関数のデプロイ）
2. Next.js のビルド
3. Vercel 本番環境への反映

が一気通貫で走る。追加の CLI 操作は不要。

## 初回セットアップ手順（設定済み・参考用）

以下は初回にこのプロジェクトを Vercel + Convex 本番環境に繋いだ時の手順。**再設定が必要になった場合（キーの再発行、別プロジェクトでの初期設定など）のみ参照すればよい。**

### 前提

- Convex ダッシュボード（[dashboard.convex.dev](https://dashboard.convex.dev/)）にログインできること
- このプロジェクトの `dev` デプロイメント（例: `dev:famous-sparrow-741`）がすでに存在すること
- **本番（Production）デプロイメントがまだ存在しない場合は先に作成する**（Convex ダッシュボードのデプロイメント切り替えから作成できる）

### 手順

#### 1. Convex側で本番デプロイキーを発行

Production デプロイキーは **プロジェクト共通の Settings ページではなく、本番デプロイメント自体の設定画面**から発行する。

1. Convex ダッシュボードでデプロイメントを **Production** に切り替える
2. そのデプロイメントの **Settings → General** タブを開く
3. **Generate Production Deploy Key** ボタンから発行

> Preview Deploy Key（プロジェクト共通の Settings ページにある）は Vercel の Preview 環境（PRごとのプレビューデプロイ）用で、Production 用とは別物。今回は Production Deploy Key を使う。

**発行時の権限（Permissions）:**

- ✅ **`deployment:deploy`** のみチェック
- 他はすべて不要（最小権限。このキーは `npx convex deploy` を実行するためだけに使う）

#### 2. Vercelでプロジェクト作成し、GitHubリポジトリと連携

通常の Vercel × GitHub 連携と同じ。この時点ではまだ Convex とは繋がっていない。

#### 3. Vercelの環境変数に `CONVEX_DEPLOY_KEY` をセット

- Vercel プロジェクトの Settings → Environment Variables
- Name: `CONVEX_DEPLOY_KEY`
- Value: 手順1で発行したキー
- 環境スコープ: **Production** のみチェック（Preview/Development は外す）

#### 4. VercelのBuild Commandを上書き

デフォルトの `next build`（package.json の `build` スクリプト）ではなく、以下に変更する。

```
npx convex deploy --cmd 'npm run build'
```

Vercel プロジェクトの Settings → Build & Development Settings → Build Command で設定する。

これにより、Vercel のビルド時に

1. Convex の本番デプロイ（関数のデプロイ）が自動実行される
2. その後 `npm run build`（= `next build`）が実行され、本番用の `NEXT_PUBLIC_CONVEX_URL` などが自動で注入される

`.env.local` の値（`dev:famous-sparrow-741` 向け）はローカル開発専用であり、Vercel側には設定不要。
