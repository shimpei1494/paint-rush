# デプロイ手順（Vercel + Convex）

## 本番URL

https://paint-rush-eight.vercel.app/

## 日常のデプロイ方法

初回セットアップ（下記）が完了していれば、**`main` ブランチに push / マージするだけ**で自動デプロイされる。

Vercel の GitHub 連携により `main` への push をトリガーに Build Command（`npx convex deploy --cmd 'npm run build'`）が自動実行され、

1. Convex の本番デプロイ（関数のデプロイ）
2. Next.js のビルド
3. Vercel 本番環境への反映

が一気通貫で走る。追加の CLI 操作は不要。

## プレビューデプロイ（ブランチごとの検証環境）

`main` 以外のブランチを push すると、Vercel が自動でプレビュー環境をビルドする。このとき Convex 側もブランチ名に対応した**専用の Convex デプロイメント**（本番とは別のバックエンド）を自動で用意し、プレビュー画面はそちらに接続される。

### 何が嬉しいか

- プレビュー画面での操作（部屋作成・プレイなど）が本番の Convex データに一切影響しない
- ブランチで変更した Convex 関数（mutation/query/スキーマ）がそのままプレビューにデプロイされるので、フロントとバックエンドの整合性が取れた状態で動作確認できる
  - もし Preview 用のキーを設定せず本番キーのままプレビューを動かすと、フロントは新しいコードなのに繋ぎ先の Convex は本番の古い関数のまま、という食い違いが起きて壊れる（このケースは Convex 側がビルドエラーとして検知して止めてくれる）

### 仕組み

1. `main` 以外のブランチに push する
2. Vercel がそのブランチのプレビュービルドを開始し、Build Command（`npx convex deploy --cmd 'npm run build'`）を実行
3. `npx convex deploy` が Preview 用の `CONVEX_DEPLOY_KEY` を検出し、**Git ブランチ名に対応した Convex デプロイメント**を自動作成（すでにあれば再利用）
4. `NEXT_PUBLIC_CONVEX_URL` がそのプレビューデプロイメントの URL に自動で差し替わった状態で `npm run build` が実行される
5. 同じブランチに再度 push すると、既存のプレビューデプロイメントとそのデータがそのまま再利用される（毎回作り直されない）

### 設定手順（設定済み・参考用）

本番用とは**別の環境変数スコープ**で Preview Deploy Key を登録する。

1. Convex ダッシュボードのプロジェクト共通の **Settings** ページ（本番デプロイメント個別の設定画面ではない）を開き、**Generate Preview Deploy Key** で発行する
   - 権限は Production Deploy Key と同様、`deployment:deploy` のみで良い
2. Vercel プロジェクトの Settings → Environment Variables で、`CONVEX_DEPLOY_KEY` という**同名の変数をもう1つ追加**する
   - Value: 手順1で発行した Preview Deploy Key
   - 環境スコープ: **Preview** のみチェック（Production/Development は外す）
3. これで `CONVEX_DEPLOY_KEY` という名前の変数が Production スコープ用・Preview スコープ用の2本存在する状態になる。Vercel はビルド環境（`VERCEL_ENV`）に応じて該当するスコープの値だけを注入するので、取り違いは起きない

> スコープの割り当てを間違えると、本番ビルドで Preview キーが使われて「`CONVEX_DEPLOY_KEY` と紐づくデプロイメントが見つからない」系のエラーになったり、逆に Preview ビルドで Production キーが使われて `Detected a non-production build environment and "CONVEX_DEPLOY_KEY" for a production Convex deployment` エラーになったりする。後者は実際に一度遭遇した（2026-08-08）。

### 制限事項

- Convex のプレビューデプロイメントは**ベータ機能**
- 無料（Free/Starter）プランでは**作成から5日で自動削除**される（Professional 以上は14日）
- 新規作成時は**DBが空の状態**。初期データが必要な場合は `--preview-run=<関数名>` でシード関数を実行できる（未設定）
- チームの**デプロイメント上限（無料プランは40）**にカウントされる

### 動作確認

2026-08-08 時点で Preview 用 `CONVEX_DEPLOY_KEY` を追加設定済みだが、**実際のプレビュービルドでの動作確認はまだ行っていない**。次に `main` 以外のブランチを push した際、Vercel のビルドログで Convex のプレビューデプロイメントが作成されること、および Preview URL で部屋の作成・参加が本番に影響せず動作することを確認する。

## 初回セットアップ手順（設定済み・参考用）

以下は初回にこのプロジェクトを Vercel + Convex 本番環境に繋いだ時の手順。**再設定が必要になった場合（キーの再発行、別プロジェクトでの初期設定など）のみ参照すればよい。**

### 前提

- Convex ダッシュボード（[dashboard.convex.dev](https://dashboard.convex.dev/)）にログインできること
- このプロジェクトの `dev` デプロイメント（例: `dev:famous-sparrow-741`）がすでに存在すること
- **本番（Production）デプロイメントがまだ存在しない場合は先に作成する**（Convex ダッシュボードのデプロイメント切り替えから作成できる）

### 手順

#### 1. Convex側で本番デプロイキーを発行

Production デプロイキーは **プロジェクト共通の Settings ページではなく、本番デプロイメント自体の設定画面**から発行する。

1. Convex ダッシュボードでデプロイメントを **Production** に切り替える
2. そのデプロイメントの **Settings → General** タブを開く
3. **Generate Production Deploy Key** ボタンから発行

> Preview Deploy Key（プロジェクト共通の Settings ページにある）は Vercel の Preview 環境（PRごとのプレビューデプロイ）用で、Production 用とは別物。今回は Production Deploy Key を使う。

**発行時の権限（Permissions）:**

- ✅ **`deployment:deploy`** のみチェック
- 他はすべて不要（最小権限。このキーは `npx convex deploy` を実行するためだけに使う）

#### 2. Vercelでプロジェクト作成し、GitHubリポジトリと連携

通常の Vercel × GitHub 連携と同じ。この時点ではまだ Convex とは繋がっていない。

#### 3. Vercelの環境変数に `CONVEX_DEPLOY_KEY` をセット

- Vercel プロジェクトの Settings → Environment Variables
- Name: `CONVEX_DEPLOY_KEY`
- Value: 手順1で発行したキー
- 環境スコープ: **Production** のみチェック（Preview/Development は外す）

#### 4. VercelのBuild Commandを上書き

デフォルトの `next build`（package.json の `build` スクリプト）ではなく、以下に変更する。

```
npx convex deploy --cmd 'npm run build'
```

Vercel プロジェクトの Settings → Build & Development Settings → Build Command で設定する。

これにより、Vercel のビルド時に

1. Convex の本番デプロイ（関数のデプロイ）が自動実行される
2. その後 `npm run build`（= `next build`）が実行され、本番用の `NEXT_PUBLIC_CONVEX_URL` などが自動で注入される

`.env.local` の値（`dev:famous-sparrow-741` 向け）はローカル開発専用であり、Vercel側には設定不要。

## 動作確認済み

上記手順で Vercel（無料プラン）へのデプロイと動作確認済み（2026-08-08）。

## Basic認証で本番アクセスを制限する

一般公開はせず、招待した人だけが本番URLを使えるようにしたい場合、`proxy.ts` に実装した Basic 認証を有効化する。

### 仕組み

- ルート直下の `proxy.ts` が、静的アセット（`_next/static` など）を除く全リクエストに対して Basic 認証を要求する
- 環境変数 `BASIC_AUTH_USER` / `BASIC_AUTH_PASSWORD` の**両方が設定されている場合のみ**認証が有効になる
- どちらか片方でも未設定なら認証をスキップする（ローカル開発 `npm run dev` では何も設定しなくてよい）

### 有効化手順

1. Vercel プロジェクトの Settings → Environment Variables を開く
2. 以下の2つを追加する（値は任意のユーザー名・パスワード）
   - `BASIC_AUTH_USER`
   - `BASIC_AUTH_PASSWORD`
   - 環境スコープ: 認証をかけたい環境（例: **Production** のみ、あるいは Preview も含める）にチェック
3. 再デプロイ（Redeploy）すると反映される。Vercel は環境変数変更を既存のデプロイに自動反映しないため、変更後は再デプロイが必要

### 無効化（一般公開に戻す）手順

Vercel の Environment Variables から `BASIC_AUTH_USER` / `BASIC_AUTH_PASSWORD` を削除して再デプロイする。

## クラウドAIエージェントにConvexを操作させる場合

Claude Code のクラウド環境など、ブラウザログインができない環境から `npx convex dev` 等を動かしたい場合の手順。

**`.env.local` の値をそのままクラウド環境にコピーしても動かない。** `CONVEX_DEPLOYMENT` や `NEXT_PUBLIC_CONVEX_URL` は接続先を示すだけで、CLI の認証情報（`npx convex login` でブラウザ経由に行うログイン）は含まれていないため。

自分のPC用のdevデプロイメント（`dev:famous-sparrow-741`）とは**別に、エージェント専用のdevデプロイメントを作って認証キーを発行する**のが公式に用意された方法（Agent Mode）。これにより、エージェントの変更と自分の変更が同じデータ/スキーマ上で衝突するのを防げる。

### 事前に確認する値

コマンド中の `team-slug` / `project-slug` / 識別子部分は環境ごとに異なるため、実行前に置き換える。

| プレースホルダー | 確認場所 | このプロジェクトでの値 |
|---|---|---|
| `team-slug` | [.env.local](../.env.local) のコメント（`# team: ...`）、または Convex ダッシュボードの URL（`dashboard.convex.dev/t/<team-slug>/...`） | `peishim` |
| `project-slug` | 同上（`# ..., project: ...`）、または上記 URL の続き（`.../<project-slug>`） | `paint-rush` |
| `dev/` 以降の識別子 | 決まった値はない。エージェントやワークツリーを区別できる**任意の一意な名前**を自分で決める（例: `dev/agent/paint-rush` や `dev/$USER-codex`） | 任意（下の例では `dev/agent/paint-rush`） |

### 手順

1. エージェント専用のdevデプロイメントを新規作成（`team-slug:project-slug:...` の部分を上表の値に置き換える）

```
npx convex deployment create --type dev --select \
  peishim:paint-rush:dev/agent/paint-rush \
  --expiration "in 5 days"
```

2. そのデプロイメント専用のDeploy Keyを発行（このデプロイメント以外にはアクセスできない）

```
npx convex deployment token create agent-token --save-env
```

3. 発行された `CONVEX_DEPLOY_KEY` を、クラウドエージェント側の環境変数（例: Claude Code のクラウド環境変数設定）に登録する

4. 自分のPCは従来どおり `npx convex deployment select dev` で自分専用のdevデプロイメントを使い続ける

`--expiration` で有効期限を切っておけば、使わなくなったエージェント用デプロイメントは自動的に無効化される。

参考: [Convex CLI — Agent Mode](https://docs.convex.dev/cli/agent-mode)
