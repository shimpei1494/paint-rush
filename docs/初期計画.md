# Paint Rush — リアルタイム陣取りバトル 実装仕様書

Convex + Next.js で作るリアルタイム同期のマルチプレイヤー陣取りゲーム。
イベント(約3時間)での実装・発表用。Convexの「リアルタイム同期・ACIDなmutation・型共有」の魅力を示すことが目的。

## 1. ゲーム概要

- 制限時間60秒。参加者はグリッドのセルをタップして自分の色に塗る。上塗りOK
- 終了時に面積(セル数)が最大の色(チーム)が勝ち
- 参加人数: 2〜6人。7人目の入室は拒否
- チーム: 6色パレット固定。同色=同チーム。デフォルトは1人1色(入室時に未使用色を自動割当)。ロビーで各自が色を変更でき、同色を選べばチームになる。人数配分は自由(1人 vs 5人でも可)
- 部屋を作った親(ホスト)だけがゲームを開始・リセットできる

## 2. 技術スタック

| 領域 | 選定 |
|---|---|
| フレームワーク | Next.js (App Router)。ゲーム画面は全て `"use client"`(実質SPA。SSR不要) |
| バックエンド | Convex(クラウド版、無料枠) |
| 言語 | TypeScript |
| スタイリング | Tailwind CSS |
| QRコード | qrcode.react(部屋参加URL表示用) |
| 認証 | なし。名前入力+localStorageに保存したplayerIdのみ |
| デプロイ | Vercel(フロント) + Convexクラウド(バックエンド) |

追加ライブラリは上記以外入れない。グリッドはCSS Gridのdivで描画(Canvas不使用)。

## 3. 画面とルーティング

| パス | 画面 | 内容 |
|---|---|---|
| `/` | トップ | 名前入力+「部屋を作る」/「部屋コードで参加」 |
| `/room/[code]` | メイン | statusに応じてロビー/カウントダウン/ゲーム/結果を出し分け(1ページ内で切替) |
| `/room/[code]/screen` | 観戦・プロジェクター用(任意、余裕があれば) | 大きいグリッド+スコアバー+残り時間+参加QR。操作不可 |

### ロビー (status: "lobby")
- 部屋コードを大きく表示+参加URLのQRコード
- 参加者一覧(名前+色)。リアルタイム更新
- 6色パレットを表示し、各自がタップで自分の色を変更(全員の画面に即反映)
- ホストにのみ「スタート」ボタン(参加者2人以上で有効化)

### カウントダウン (status: "countdown")
- 3, 2, 1 を全員の画面に表示(開始時刻タイムスタンプからクライアント計算)

### ゲーム中 (status: "playing")
- グリッド(20×20)。タップで自分の色に塗る。楽観的更新で即時反映
- 上部に色ごとのリアルタイムスコアバー(セル数の割合)と残り時間
- 残り時間は `endsAt` タイムスタンプからクライアントで毎フレーム計算(サーバーポーリングしない)
- タップのクールダウン: 1人あたり300ms(サーバー側で検証、クライアント側でも連打を無視)

### 結果 (status: "finished")
- 色ごとの獲得セル数ランキング。優勝色を大きく表示
- ホストにのみ「もう一回」ボタン(セル全削除+ロビーへ戻る)

## 4. Convexスキーマ (`convex/schema.ts`)

```ts
rooms: defineTable({
  code: v.string(),            // 4文字英大文字のランダムコード
  hostPlayerId: v.string(),
  status: v.union(v.literal("lobby"), v.literal("countdown"),
                  v.literal("playing"), v.literal("finished")),
  startsAt: v.optional(v.number()),  // カウントダウン終了=ゲーム開始時刻
  endsAt: v.optional(v.number()),    // ゲーム終了時刻
  gridSize: v.number(),              // デフォルト20
}).index("by_code", ["code"]),

players: defineTable({
  roomId: v.id("rooms"),
  playerId: v.string(),        // クライアント生成のUUID(localStorage保存)
  name: v.string(),
  color: v.string(),           // 6色パレットのいずれか
  lastPaintedAt: v.optional(v.number()),
}).index("by_room", ["roomId"]),

cells: defineTable({
  roomId: v.id("rooms"),
  x: v.number(),
  y: v.number(),
  color: v.string(),
}).index("by_room", ["roomId"])
  .index("by_room_pos", ["roomId", "x", "y"]),
```

重要: セルは1セル=1ドキュメント(塗られたセルのみ作成、upsert)。グリッド全体を1ドキュメントの配列にしないこと。全タップが同一ドキュメント書き込みになりOCCリトライのボトルネックになるため。

色パレット(6色固定): `#ef4444`(赤) `#3b82f6`(青) `#22c55e`(緑) `#eab308`(黄) `#a855f7`(紫) `#f97316`(橙)

## 5. サーバー関数 (`convex/rooms.ts` / `convex/game.ts`)

### mutations
- `createRoom({ playerId, name })` — 部屋作成。コード生成、作成者をホスト+先頭色でplayers登録。roomのcodeを返す
- `joinRoom({ code, playerId, name })` — 入室。検証: 部屋存在 / status==="lobby"(それ以外は観戦扱いでエラーコード返却) / 人数<6(超過は拒否) / 同playerIdの再入室は既存レコード返却(リロード対応)。未使用の色を自動割当
- `changeColor({ roomId, playerId, color })` — ロビー中のみ。自分の色を変更(重複選択OK=チーム)
- `startGame({ roomId, playerId })` — ホストのみ。参加者2人以上を検証。status="countdown"、startsAt=now+3秒、endsAt=startsAt+60秒 に設定し、`ctx.scheduler.runAt(startsAt, internal.game.beginPlaying)` と `ctx.scheduler.runAt(endsAt, internal.game.endGame)` を予約
- `paint({ roomId, playerId, x, y })` — 心臓部。検証: status==="playing" / 現在時刻がstartsAt〜endsAt内 / 座標が範囲内 / クールダウン(now - lastPaintedAt >= 300ms)。by_room_posでセルを検索し、あればcolor更新、なければinsert。playerのlastPaintedAt更新
- `resetRoom({ roomId, playerId })` — ホストのみ。該当roomのcells全削除、status="lobby"に戻す

### internal mutations(スケジューラから呼ばれる)
- `internal.game.beginPlaying({ roomId })` — status="playing"
- `internal.game.endGame({ roomId })` — status="finished"

### queries
- `getRoom({ code })` — 部屋+players一覧を返す(ロビー・結果画面用)
- `getCells({ roomId })` — 該当roomの全セル。スコアはクライアント側でreduce集計

## 6. クライアント実装の要点

1. **playerId**: 初回アクセス時に `crypto.randomUUID()` で生成しlocalStorageへ。名前もlocalStorageに保存し再入力を省く
2. **楽観的更新**: `paint` は `useMutation(api.game.paint).withOptimisticUpdate(...)` で `getCells` のローカル結果を即時書き換える(自分のタップが0msで反映される)
3. **タイマー/カウントダウン**: `startsAt` / `endsAt` を元に `requestAnimationFrame` または `setInterval(100ms)` でクライアント計算。サーバーに問い合わせない
4. **グリッド描画**: `grid grid-cols-20` のdiv 400個。セルコンポーネントは `React.memo` 化し、色が変わったセルだけ再レンダリング
5. **スマホ操作性**: セルはタップしやすいサイズに(`touch-action: manipulation` でダブルタップズーム抑止、`user-select: none`)。ビューポートは `maximum-scale=1`
6. **状態出し分け**: `/room/[code]` は `getRoom` のstatusを見てロビー/カウントダウン/ゲーム/結果を同一ページ内で切替

## 7. セットアップ手順

```sh
npx create-next-app@latest paint-rush --ts --tailwind --app
cd paint-rush && npm install convex qrcode.react
npx convex dev   # GitHubログイン → プロジェクト作成 → convex/ フォルダ生成、以後実行しっぱなし
```

- `app/ConvexClientProvider.tsx` を作成し(公式Quickstart通り)、`app/layout.tsx` でラップ
- 環境変数 `NEXT_PUBLIC_CONVEX_URL` は `npx convex dev` が `.env.local` に自動設定

参考: https://docs.convex.dev/quickstart/nextjs
AIエージェント向けドキュメント索引: https://docs.convex.dev/llms.txt

## 8. デプロイ(Vercel)

1. GitHubにpushしVercelにインポート
2. Build Commandを `npx convex deploy --cmd 'npm run build'` に変更
3. Convexダッシュボードで Deploy Key を発行し、Vercelの環境変数に `CONVEX_DEPLOY_KEY` を設定(これでビルド時に本番Convexへ関数がデプロイされ、`NEXT_PUBLIC_CONVEX_URL` も本番URLに自動設定される)

参考: https://docs.convex.dev/production/hosting/vercel

## 9. 実装優先順位(時間が足りない場合の切り捨て順)

1. 【必須】部屋作成/入室/色自動割当 → ロビー同期 → paint+リアルタイム反映 → 終了判定と結果
2. 【重要】スコアバー、カウントダウン演出、もう一回ボタン
3. 【任意】観戦用 `/screen`、QRコード、爆弾機能(3×3を塗る特殊タップ。デモでのライブ実装ネタに残しておくのも良い)

## 10. 発表で語れるConvexの見せ場(実装時に意識)

- `useQuery` を購読するだけで全端末同期(WebSocket/pub-subのコード0行)
- mutationの自動直列化: 「残り1枠に2人同時入室」「同一セルへの同時タップ」が素朴なコードで正しく動く
- `ctx.scheduler.runAt` でゲーム終了処理(外部ジョブキュー不要)
- サーバー関数の型がそのままフロントに推論される(APIの型二重管理なし)
- 楽観的更新の自動ロールバック
